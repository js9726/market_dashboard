Read paths: the snapshot API overlays TradingView on a static baseline. Breadth/screeners are database-first, with a 15-minute age gate on static fallback. Live quotes poll every 30 seconds; brief cache every 60 seconds. Server intraday brief generation is snapshot-fed and explicitly lacks live web access, unlike the separate search-grounded daily Python lane.

Auth: current code uses owner/member/pending/denied, mapping legacy allowed to member. OAuth and Prisma support identity; machine ingest/cron/bridge endpoints apply their own token checks where middleware permits passage. This is an architecture description, not a certification of every route's security.

Persistence: MorningBriefCache stores briefs; WikiTradeVerdict stores ticker reviews; Position/TradeFill/LiveQuote store broker truth; TradeRecord and journal models store plans/history; DailyScreenerRun and TelegramDelivery store final runs and delivery receipts. Held-position journal views merge broker truth with sheet plan fields.

4. Why the repeated Python scripts exist

The _update_brief files are historical patch steps, not four live app versions. They revise saved June 2026 JSON. All four were ignored local leftovers and have now been archived. Their bytes differed: sequential revisions, not exact duplicates. Pulling GitHub alone could not remove them.

Saved June 14 brief
  → _update_brief_2026-06-14.py       → v2: GFS + fixed persona scores
  → _update_brief_v3_2026-06-14.py    → v3: NOK + Conviction scoring
  → _update_brief_v4_2026-06-15.py    → v4: TWLO interpretation correction
  → _update_brief_v5_2026-06-15.py    → v5: fixed June 15 premarket data

They do not fetch fresh prices/news. The version number belongs to one historical brief revision. They are unnecessary for the current normal brief pipeline and are good archival candidates, but “no repository caller found” does not prove that no external scheduled/manual workflow uses them.
